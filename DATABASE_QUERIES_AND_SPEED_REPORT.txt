1. WHAT HAPPENS WHEN DATA IS MISSING IN THE DATABASE?
================================================================================

We audited every controller, query, and frontend consumer to determine exactly
what happens when database records, columns, or relations are missing:

--------------------------------------------------------------------------------
SCENARIO A: A Course Has 0 Lessons or 0 Modules (CRITICAL RUNTIME CRASH)
--------------------------------------------------------------------------------
Location: `adhoc_test_lms/src/pages/student/CoursePlayer.jsx` (Lines 122 & 610-618)
What Happens:
  1. When a course has no modules or no lessons in the DB, `courseData.data.modules`
     is empty (`[]`).
  2. `activeItem` remains `null`.
  3. When React renders the video control card at Line 610:
       {activeItem.title}
       Duration: {activeItem.duration} mins
       onClick={() => handleLessonComplete(activeItem.id)}
  4. React throws an UNHANDLED RUNTIME EXCEPTION:
       TypeError: Cannot read properties of null (reading 'title')
  5. The entire page crashes with a blank white screen for the student!
How to Fix:
  Add an `activeItem` safety guard returning an empty-curriculum notice:
  "No published lessons available for this course yet."


--------------------------------------------------------------------------------
SCENARIO B: A Quiz Has 0 Questions in the Database (FATAL SQL / 500 ERROR)
--------------------------------------------------------------------------------
Location: `lms_backend/controllers/quizController.js` (Lines 138 - 151)
What Happens:
  1. When a student submits a quiz that has no questions entered:
       let totalPoints = 0;
       for (const question of quiz.questions) { totalPoints += question.points; }
       const percentage = Math.round((earnedPoints / totalPoints) * 100);
  2. Because `totalPoints` is 0, JavaScript computes `0 / 0` = `NaN`!
  3. The controller then executes:
       await QuizAttempt.create({ ... percentage: NaN });
  4. MySQL crashes on SQL insert:
       Data truncated for column 'percentage' / Incorrect integer value: 'NaN'
  5. Backend returns HTTP 500 "Server error" to the student!
How to Fix:
  Add a zero-guard:
  const percentage = totalPoints > 0 ? Math.round((earnedPoints / totalPoints) * 100) : 0;


--------------------------------------------------------------------------------
SCENARIO C: Certificate Generated for Deleted/Orphaned User or Course (500 ERROR)
--------------------------------------------------------------------------------
Location: `lms_backend/controllers/certificateController.js` (Lines 150 & 166)
What Happens:
  1. If an admin deletes a user or a course, but certificate rows remain in the DB:
  2. PDF generator runs:
       doc.text(certificate.user.name, 0, 240, { align: 'center' });
       doc.text(`"${certificate.course.title}"`, 0, 350, { align: 'center' });
  3. If `certificate.user` or `certificate.course` is null:
       TypeError: Cannot read properties of null (reading 'name')
  4. PDF generation fails and user gets HTTP 500 error instead of downloading PDF.
How to Fix:
  Use optional chaining and fallbacks:
  certificate.user?.name || 'Valued Learner'
  certificate.course?.title || 'Certification Course'


--------------------------------------------------------------------------------
SCENARIO D: Entire Courses Table is Empty (SAFE)
--------------------------------------------------------------------------------
Location: `courseController.js` & `Catalog.jsx`
What Happens:
  - Backend returns `{ success: true, count: 0, data: [] }`.
  - `Catalog.jsx` displays the curated "No courses found" message with "Reset Filters" button.
  - `Home.jsx` gracefully loads static curated stats.
  - Status: Gracefully handled without crashes.


--------------------------------------------------------------------------------
SCENARIO E: User Table is Empty / Admin Deleted (SAFE REJECTION)
--------------------------------------------------------------------------------
Location: `authController.js`
What Happens:
  - User login returns HTTP 401 "Email was not registered".
  - Frontend displays Sonner error toast.
  - Note: Initial super-admin seed data is required if resetting a fresh database.


--------------------------------------------------------------------------------
SCENARIO F: Missing/Orphaned Foreign Keys on Deletion (SQL CONSTRAINT FAILURE)
--------------------------------------------------------------------------------
Location: `lms_backend/models/associations.js`
What Happens:
  - `associations.js` does NOT specify `onDelete: 'CASCADE'`.
  - When an admin attempts to delete a course that has modules or subscriptions,
    MySQL rejects the deletion with foreign key constraint error:
      ER_ROW_IS_REFERENCED_2 (Cannot delete or update a parent row)
How to Fix:
  Add `onDelete: 'CASCADE'` or soft-delete flags on course/module associations.

2. DATABASE QUERY PERFORMANCE AUDIT & BOTTLENECK ANALYSIS
================================================================================

--------------------------------------------------------------------------------
BOTTLENECK #1: Missing Database Indexes (Full Table Scans)
--------------------------------------------------------------------------------
Current State:
  In `Subscription.js`, `UserDevice.js`, `Module.js`, `Lesson.js`, and `Ticket.js`:
  Zero secondary indexes are declared.
Impact:
  - On every login, `UserDevice.findOne({ where: { userId, deviceType, isActive } })`
    scans the entire table row by row (O(N)).
  - On every course access check, `Subscription.findOne({ where: { userId, courseId, status } })`
    scans every subscription ever created row by row (O(N)).
  - As users grow to 1,000+, query latency spikes from 2ms to 200ms+.

--------------------------------------------------------------------------------
BOTTLENECK #2: Sequential Await Queries Instead of Parallel Execution
--------------------------------------------------------------------------------
Location: `adminStatsController.js` and `analyticsController.js`
Current State:
  5 to 7 separate `await` statements run in sequence:
    const totalStudents = await User.count(...);
    const totalAdmins = await User.count(...);
    const totalCourses = await Course.count(...);
    const activeSubscriptions = await Subscription.count(...);
    const revenueResult = await Subscription.sum(...);
Impact:
  5 queries taking 30ms each = 150ms roundtrip delay.
  With `Promise.all()`, all 5 execute simultaneously in ~30ms total (5x faster).

--------------------------------------------------------------------------------
BOTTLENECK #3: Unbounded Memory Query in Analytics
--------------------------------------------------------------------------------
Location: `analyticsController.js` (Lines 37-52)
Current State:
  Fetches ALL subscriptions and ALL users over the past 3 years into Node.js
  memory and runs JavaScript `.filter()` loops for every single day, month, and year!
Impact:
  - With 5,000 subscriptions, this loads megabytes of memory and locks the Node event loop.
  - Can be replaced with SQL aggregation (`GROUP BY DATE(createdAt)`) executing in 5ms.

--------------------------------------------------------------------------------
BOTTLENECK #4: Excessive User Progress Over-Fetching
--------------------------------------------------------------------------------
Location: `progressController.js` (Line 114)
Current State:
  `Progress.findAll({ where: { userId } })` fetches every lesson progress record
  across ALL courses the user has ever touched, instead of filtering by the current
  course's lesson IDs.

3. WEBSITE ACCURACY & MAXIMUM SPEED OPTIMIZATIONS
================================================================================

--------------------------------------------------------------------------------
SPEED ENHANCEMENT #1: HTTP Gzip / Brotli Compression Middleware
--------------------------------------------------------------------------------
Location: `lms_backend/server.js`
Finding:
  Express is currently sending all JSON responses, HTML documents, and static
  assets WITHOUT compression.
Expected Impact:
  - `dist/index.html` (104 KB) -> reduced to ~16 KB (85% reduction)
  - `dist/assets/vendor.js` (328 KB) -> reduced to ~108 KB (67% reduction)
  - `dist/assets/index.js` (119 KB) -> reduced to ~32 KB (73% reduction)
  - API JSON payloads -> reduced by 60-80%
  Result: Website page load times drop by 2x to 3x across 4G and mobile networks.

--------------------------------------------------------------------------------
SPEED ENHANCEMENT #2: Database Compound Indexing
--------------------------------------------------------------------------------
Add indexes to `Subscription`, `UserDevice`, and `Progress` models:
  - `subscriptions`: `['userId', 'courseId', 'status']`, `['status', 'endDate']`
  - `user_devices`: `['userId', 'deviceType', 'isActive']`, `['deviceFingerprint']`
  - `modules`: `['courseId', 'order']`
  - `lessons`: `['moduleId', 'order']`
Result: Queries execute in sub-millisecond O(log N) indexed B-tree lookups.

--------------------------------------------------------------------------------
SPEED ENHANCEMENT #3: Parallelize Database Queries with Promise.all
--------------------------------------------------------------------------------
In `adminStatsController.js` and `courseController.js`:
Execute independent queries concurrently. Cuts admin dashboard response times
from ~300ms down to ~50ms.

--------------------------------------------------------------------------------
SPEED ENHANCEMENT #4: Database Connection Pool Tuning
--------------------------------------------------------------------------------
In `lms_backend/config/database.js`:
Increase pool max from 5 to 20 connections so concurrent users don't queue
waiting for free database sockets.
