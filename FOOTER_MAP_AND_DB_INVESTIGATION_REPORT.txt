2. Why the map section "sometimes appears, but most of the time is not showing".

================================================================================
ISSUE 1: MAP PRESENT IN GITHUB BUT MISSING IN ONLINE INSPECT CODE
================================================================================
Symptom:
- You pushed the Map section to GitHub (in Footer.jsx).
- When opening https://adhocnetwork.tech and inspecting the footer DOM, the HTML
  for the Map section is not there at all (only 3 columns exist: Brand, Newsletter,
  and Base).
- Sometimes it shows up (e.g. on new devices or incognito), but most of the time
  it does not.

Root Cause:
- The frontend registers a Service Worker in `adhoc_test_lms/public/service-worker.js`.
- Inside `service-worker.js`, the fetch handler implements an unversioned
  "Cache-First" caching policy for all non-API GET requests:
  
    caches.open("static-assets").then((cache) =>
      cache.match(event.request).then(
        (response) => response || fetch(event.request)...
      )
    );

- When any visitor opens the website, their browser stores the HTML document
  (index.html) in the browser's persistent Cache Storage.
- On subsequent visits, the browser serves the STALE OLD index.html from cache
  without asking the server if an update exists.
- Because the old index.html references the older JavaScript bundle (built before
  the map was added), the browser executes the old code.
- When inspecting the DOM via DevTools, you are inspecting the old cached build,
  which does not contain the Map component.

Why it behaves inconsistently ("sometimes present, most of the time not"):
- Normal Browsing (Returning Users): The service worker intercepts requests and
  serves the old cached version (map missing).
- Incognito / Private Window / New Browsers: No service worker cache exists, so
  the browser downloads the latest build from the server (map appears).
- Hard Refresh (Ctrl + Shift + R): Temporarily bypasses service worker caching.

ISSUE 2: MAP SECTION LOADS WITH A GREY BOX & BROKEN/SAD PAGE ICON
================================================================================
Symptom:
- When the latest build is loaded (e.g., in incognito or fresh browser), the
  "MAP LOCATION" header appears, but the iframe displays a grey box with a
  crashed/sad file icon and does not display Google Maps.

Root Cause:
- Backend Content Security Policy (CSP) blocking Google Maps iframes.
- In `lms_backend/server.js` (lines 48-62), the Express server uses Helmet to
  enforce Content Security Policy headers:

    app.use(helmet({
      contentSecurityPolicy: {
        directives: {
          defaultSrc: ["'self'"],
          scriptSrc: ["'self'", "'unsafe-inline'", "https://checkout.razorpay.com"],
          frameSrc: ["'self'", "https://api.razorpay.com", "https://tds.razorpay.com", "https://checkout.razorpay.com"],
          ...
        }
      }
    }));

- The `frameSrc` directive dictates which external domains are permitted to load
  inside an <iframe> tag.
- Currently, `frameSrc` ONLY permits Razorpay domains (`api.razorpay.com`,
  `tds.razorpay.com`, `checkout.razorpay.com`).
- It DOES NOT permit `https://www.google.com` or `https://maps.google.com`.
- When Chrome/Firefox encounters:
    <iframe src="https://www.google.com/maps/embed?..." ... />
  the browser reads the server CSP header, blocks the connection to Google Maps,
  and renders a blank/crashed grey box with the broken file icon.

ISSUE 3: DATABASE DATA NOT SHOWING ON THE ONLINE WEBSITE
================================================================================
Symptom:
- Database contains data (e.g., courses, student feedback), but the online
  website sometimes shows no courses or hardcoded fallback testimonials.

Root Causes:
1. Fallback Mock Data Triggered:
   - In `adhoc_test_lms/src/pages/public/Home.jsx`, if the network request to
     `/api/feedbacks/home` or `/api/courses` encounters any delay, error, or
     cache mismatch, the component catches the error and silently displays
     hardcoded mock data (e.g. Dr. Sarah Chen, Michael Rodriguez, Priya Sharma)
     or an empty course list.

2. API URL Fallback in Older Cached Bundles:
   - In `adhoc_test_lms/src/services/api.js`:
       const API_URL = import.meta.env.VITE_API_URL || "http://localhost:5000/api";
   - If an older bundle is served by the Service Worker that was built without
     the production `.env` variable, all API requests attempt to connect to
     `http://localhost:5000/api` on the end-user's device instead of the live
     domain (`https://adhocnetwork.tech/api`). Since ordinary visitors do not have
     Node.js running on port 5000 locally, the requests fail instantly.

3. Express Rate Limiter IP Collisions:
   - In `lms_backend/server.js`, `express-rate-limit` is active:
       app.set('trust proxy', 1);
       app.use('/api', limiter);
   - Behind Hostinger CDN / reverse proxy, multiple incoming requests may share
     proxy headers. When rate limit thresholds are reached, the server returns
     HTTP 429 ("Too many requests"), causing API queries to fail until the window
     resets.
